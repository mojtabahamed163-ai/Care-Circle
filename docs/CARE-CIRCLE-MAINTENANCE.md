# دليل التشغيل والصيانة — Care Circle

**الحالة:** دليل مستقل أُضيف ضمن فرع `secondary-maintenance` في 2026-10-30.

هذا الدليل يصف بنية المستودع الحالية وطريقة تشغيله وصيانته. لا يحتوي أسرارًا، ولا يُغني عن إعداد مشروع WebDev/OAuth أو قاعدة بيانات اختبار مصرح بها.

## 1. بنية المشروع

- `client/`: تطبيق React/Vite. يبدأ من `client/src/main.tsx`، والتوجيه الحالي في `client/src/App.tsx`، والواجهة الرئيسية في `client/src/pages/Home.tsx`.
- `client/public/`: ملفات عامة ثابتة، ومنها `manus-routes.json` وملف علامة Care Circle وجامع سجلات التطوير.
- `server/_core/`: تشغيل Express/Vite، سياق tRPC، تكامل المنصة، التخزين، وضبط القيم العامة. ملفات OAuth والجلسات موجودة هنا، لكنها خارج نطاق صيانة هذا الفرع.
- `server/routers.ts`: عقد tRPC والتحقق من مدخلات الطلبات. إجراءات الرعاية تستدعي طبقة البيانات بدل الوصول المباشر من العميل.
- `server/care-db.ts`: عمليات بيانات الأسرة والعضوية والمهام والأدوية والمواعيد والسجل والاحتياجات وجهات الاتصال والتعاون والتصدير والحذف.
- `drizzle/schema.ts`: مخطط MySQL/Drizzle. مجلد `drizzle/` يحوي ترحيلات متسلسلة ولقطات المخطط.
- `shared/`: أنواع وثوابت وأدوات المنطقة الزمنية المشتركة بين العميل والخادم.
- `vite.config.ts`: إعداد البناء وخادم التطوير وجامع سجلات التطوير. لا تُضاف أسرار إلى هذا الملف.

## 2. التثبيت والتشغيل المحلي

استخدم نسخة اختبار غير إنتاجية وقاعدة بيانات منفصلة ببيانات اصطناعية فقط:

```bash
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

يقرأ `pnpm dev` المنفذ من `PORT` ويستخدم 3000 افتراضيًا. لتشغيل الواجهة الثابتة فقط:

```bash
pnpm dev:static
```

هذا الأمر لا يشغل Express أو tRPC، ولذلك لا يصلح لاختبار الوظائف المحمية.

## 3. قاعدة البيانات والترحيلات

المشروع يستخدم MySQL عبر Drizzle. ترتيب الترحيلات الحالي هو `0000` إلى `0008`، وتشمل المستخدمين، الأسر والعضوية والدعوات، المهام، الأدوية والجرعات، المواعيد والسجل، القوائم المنزلية، التعاون، الملخصات، والتفضيلات والأحداث الداخلية للتنبيهات.

لتطبيق ترحيلات موجودة على قاعدة الاختبار:

```bash
pnpm db:migrate
```

لا تستخدم `pnpm db:push` على قاعدة مشتركة أو إنتاجية كخطوة استكشافية؛ الأمر يولد ويطبق تغييرات مخطط وقد يكون مدمرًا حسب الفرق. أي ترحيل جديد يجب أن يكون additive قدر الإمكان، ويُراجع مع نسخة احتياطية واختبار استعادة.

اختبار MySQL الاختياري محمي بمتغير `CARE_CIRCLE_TEST_DATABASE_URL`. استخدم قاعدة loopback منفصلة يبدأ اسمها بـ `carecircle_test_`، ولا توجهه إلى قاعدة Manus المشتركة أو إلى بيانات عائلية حقيقية.

## 4. متغيرات البيئة

انسخ `.env.example` إلى `.env` محليًا فقط، ولا تحفظ `.env` في Git:

| المتغير | الغرض |
| --- | --- |
| `DATABASE_URL` | اتصال MySQL/MariaDB لبيئة التشغيل أو الاختبار المصرح بها. |
| `MANUS_PROJECT_ID` | معرّف مشروع WebDev؛ قيمة إعداد، وليست سرًا بحد ذاتها، لكنها لا تُخمن. |
| `MANUS_OAUTH_PORTAL_URL` | بوابة دخول Manus. لا تغيّرها ضمن فرع الصيانة هذا. |
| `MANUS_OAUTH_API_URL` | واجهة OAuth. لا تغيّرها ضمن فرع الصيانة هذا. |
| `MANUS_JWT_SECRET` | سر توقيع جلسات التطبيق؛ لا يكتب في المستودع أو السجلات. |
| `PORT` | منفذ Express، والافتراضي 3000. |
| `CARE_CIRCLE_TEST_DATABASE_URL` | اتصال اختبار MySQL المحلي المعزول عند تشغيل `pnpm test:mysql`. |

القيم السرية تُحفظ في Secret Store أو في ملف محلي غير متعقب. لا تُرسل قيمة حقيقية في تقرير أو مشكلة GitHub.

## 5. الفحص والاختبارات والبناء

الأوامر الأساسية:

```bash
pnpm check       # فحص TypeScript
pnpm test        # اختبارات Vitest الافتراضية
pnpm test:mysql  # اختبار MySQL opt-in، مع قاعدة loopback منفصلة فقط
pnpm build       # بناء Vite ثم حزمة الخادم
pnpm start       # تشغيل dist/index.js بعد البناء
```

الاختبار المتخطى لا يُعد نجاحًا. إذا لم تضبط `CARE_CIRCLE_TEST_DATABASE_URL` فسيُتخطى اختبار MySQL الاختياري ويجب تسجيل ذلك صراحة.

## 6. النسخ الاحتياطي والاستعادة

لا توجد في هذا المستودع عملية نسخ احتياطي تلقائية أو وعد احتفاظ مستقل. قبل أي ترحيل أو حذف واسع، ينفذ مسؤول قاعدة البيانات نسخة مشفرة في مخزن مصرح به، خارج Git، مع اختبار استعادة على قاعدة غير إنتاجية.

مثال MySQL عام لقاعدة اختبار أو staging (استبدل القيم محليًا ولا تضع كلمة المرور في سطر الأوامر إن كانت البيئة تسجل التاريخ):

```bash
mysqldump --single-transaction --routines --triggers --databases carecircle_test \
  > carecircle_test-$(date +%F).sql

mysql carecircle_test < carecircle_test-YYYY-MM-DD.sql
```

تحقق بعد الاستعادة من عدد الجداول، تطبيق كل ترحيلات Drizzle، ونجاح `pnpm check` و`pnpm test`. لا تستعد نسخة إنتاج فوق قاعدة تطوير مشتركة. احتفظ بالنسخ وفق سياسة مالك البيانات؛ التطبيق نفسه لا يحدد مدة احتفاظ قانونية عامة.

## 7. صيانة واستكشاف أخطاء شائعة

- **فشل اتصال قاعدة البيانات:** تحقق من `DATABASE_URL`، وصول الشبكة، اسم القاعدة، وتطبيق الترحيلات. لا تبدل قاعدة المشروع المشتركة بقاعدة عشوائية.
- **فشل OAuth أو الجلسة:** خارج نطاق هذا الفرع. لا تعدّل `MANUS_OAUTH_API_URL` أو ملفات OAuth والجلسات؛ سجّل المشكلة للحساب المسؤول عنها.
- **صفحة بلا وظائف tRPC:** تأكد من تشغيل `pnpm dev` بدل `pnpm dev:static`، وأن `PORT` متاح.
- **تحذير الحزمة أثناء البناء:** راجع [تحليل البناء والأداء](./BUILD-PERFORMANCE.md). لا ترفع حد التحذير فقط لتخفي حجمًا متزايدًا.
- **سجلات التطوير:** تم تقليل التقاط البيانات الحساسة في جامع السجلات. لا تستخدم بيئة معاينة عامة ببيانات عائلية حقيقية، واحذف `.manus-logs/` عند انتهاء جلسة الاختبار.
- **بيانات اختبار ملوثة:** أوقف الاختبار، اعزل قاعدة جديدة باسم `carecircle_test_...`، ولا تحذف بيانات قاعدة مشتركة دون إجراء معتمد.

## 8. حدود المسؤولية في هذا الفرع

لم يُنفذ هنا تسجيل دخول OAuth حقيقي، اختبار هاتف فعلي، نشر، دفع، بريد، أو نقل/إصلاح نظام الإشعارات. كما لم تُعدّل إعدادات OAuth أو الجلسات أو واجهات الهاتف أو عامل التنبيهات. أي بند يعتمد على هذه الأنظمة يجب أن يبقى مفتوحًا في تقرير التسليم.
